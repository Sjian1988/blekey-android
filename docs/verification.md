## 调试

```bash
adb logcat -s BleKey                                  # 每一帧收发的原始 hex
adb shell dumpsys deviceidle whitelist | grep blekey  # 有记录 = 已加电池白名单
adb shell dumpsys jobscheduler | grep -A6 KeepAliveJob
adb shell dumpsys alarm | grep KEEPALIVE              # flags=0x8 = ALLOW_WHILE_IDLE
```

App 内「高级设置 → 运行日志」也能展开看每帧 `rx cmd=.. key=..`，对照 [protocol.md](protocol.md) 的指令表判断卡在哪一步。

## 已知限制

1. **必须先在原厂 App 里解绑旧设备**，否则配对会被拒（App 会提示）
2. BLE 连接是独占的，与原厂 App 不能同时用 —— 用「让给原 App（10 分钟）」切换
3. 首次配对需要车机在附近；之后 `autoConnect` 白名单会一直记着这台车
4. Android 12+ 需要通知权限，否则前台服务不显示（连接仍继续）
5. 部分 ROM（含 HyperOS）会主动清理后台，必须加电池白名单和自启动
6. 车机锁配置无法读回，开锁节奏固定写在客户端里（见 [protocol.md](protocol.md) §6）
7. 「打开 App 即自动开尾门」被明确否掉：等于把无关动作绑到不可撤销的机械动作上，误唤醒或网页深链都会让尾门弹开。公开的 `blekey://trunk` 深链也一并移除
8. 语音助手拉起本 App 的方案实测不可行（非商店自签名应用进不了云端应用词典），不要再重复尝试
